# 校园智能问答助手上线方案

## 1. 项目现状

当前项目已整理为可本地运行、可通过 Docker Compose 部署的校园智能问答系统，代码仓库为：

```text
https://github.com/sana35421/school-ai
```

当前部署范围：

- 前端：Vue 3 构建后由 Nginx 提供服务。
- 后端：Spring Boot 3 + Java 17。
- 数据库：MySQL 8.0，使用 `utf8mb4`。
- 缓存：Redis 7 Alpine。
- AI：Dify Cloud 或独立部署的 Dify API。
- 编排：Docker Compose。

项目根目录的 Compose 默认只启动业务服务：`mysql`、`redis`、`backend`、`frontend`。旧版本地 Dify 配置保留在 `local-dify` profile 中，不应在没有完整依赖和版本确认时启动。

## 2. 上线目标

上线前必须完成以下目标：

1. 登录接口正常返回 token、中文姓名和角色。
2. 普通用户可以创建对话、查看历史并接收 SSE 流式回答。
3. Dify 应用可以正常调用模型和知识库。
4. 导员和管理员权限边界正确。
5. 数据库、密钥和用户隐私得到保护。
6. 发布过程可重复，故障时可以回滚代码和数据库。

## 3. 配置管理

### 3.1 环境变量

使用根目录 `.env.example` 作为模板，在本地和服务器分别创建 `.env`：

```env
MYSQL_PASSWORD=强数据库密码
DIFY_API_BASE=https://api.dify.ai/v1
DIFY_API_KEY=app-有效的Dify应用Key
JWT_SECRET=至少32位随机字符串
```

`.env` 不得提交 Git。曾经在聊天、终端或远程仓库中暴露过的 GitHub Token、Dify Key、数据库密码和 JWT Secret 必须撤销并重新生成。

### 3.2 Dify 配置

Dify 负责模型调用、知识库检索和聊天应用编排。上线前需要：

- 配置 DeepSeek 或其他模型供应商。
- 导入经过审核的校园政策、竞赛和常见问题文档。
- 将知识库关联到聊天应用。
- 发布应用并生成应用 API Key。
- 使用测试问题验证知识库命中和兜底回答。

## 4. 本地生产验证

在 `D:\school-ai` 执行：

```powershell
docker info
docker compose config
docker compose up -d --build
docker compose ps
```

验收内容：

- 浏览器访问 `http://localhost`。
- 使用测试账号登录，确认中文姓名和角色显示正常。
- 发送竞赛或政策问题，确认可以收到流式回答。
- 刷新页面后确认历史对话仍存在。
- 用导员、管理员账号分别验证权限。
- 检查 `frontend`、`backend` 日志没有持续报错。
- 确认 MySQL、Redis 数据卷未被删除。

常用检查命令：

```powershell
docker compose ps
docker compose logs --tail=100 backend
docker compose logs --tail=100 frontend
```

## 5. 云服务器部署

推荐环境：Ubuntu 22.04、4 核 CPU、8 GB 内存、40 GB 以上可用磁盘，配置 2 GB Swap。

安全组只开放：

- `22`：SSH 管理
- `80`：HTTP
- `443`：HTTPS

不要开放 `3306` 和 `6379`。

### 5.1 获取代码

```bash
cd /opt
sudo git clone https://github.com/sana35421/school-ai.git
cd /opt/school-ai
```

### 5.2 配置服务器环境

```bash
cp .env.example .env
nano .env
docker compose config --services
docker compose config --quiet
```

使用 Dify Cloud 时填写：

```env
DIFY_API_BASE=https://api.dify.ai/v1
```

使用独立 Dify 时填写服务器可以访问的实际 API 地址。不要填写本地电脑上的 `docker-api-1` 等容器名。

### 5.3 镜像无法拉取时

若服务器无法稳定访问 Docker Hub，可以在本地导出镜像：

```powershell
docker save school-ai-backend:latest school-ai-frontend:latest mysql:8.0 redis:7-alpine nginx:latest -o school-ai-images.tar
scp .\school-ai-images.tar root@服务器公网IP:/opt/school-ai/
```

服务器导入：

```bash
cd /opt/school-ai
docker load -i school-ai-images.tar
docker compose up -d
docker compose ps
```

## 6. 发布流程

### 6.1 代码发布

```powershell
git status
git add .
git commit -m "描述修改内容"
git push origin main
```

### 6.2 服务器更新

```bash
cd /opt/school-ai
git pull --ff-only origin main
docker compose up -d --build backend frontend
docker compose ps
```

只修改前端时重建 `frontend`，只修改后端时重建 `backend`。修改环境变量后重新创建受影响的服务。

## 7. 备份与回滚

更新前备份 MySQL：

```bash
mkdir -p /opt/school-ai/backups
docker exec school-ai-mysql mysqldump -uroot -p'数据库密码' school_ai > /opt/school-ai/backups/school_ai_$(date +%F_%H%M).sql
```

回滚代码：

```bash
git log --oneline -5
git checkout 稳定提交ID
docker compose up -d --build
```

恢复数据库前停止后端写入，恢复后再启动后端。生产环境禁止执行：

```bash
docker compose down -v
```

该命令会删除数据卷，可能造成业务数据丢失。

## 8. 域名和 HTTPS

公网 IP 验收通过后再配置域名：

1. 将域名 A 记录指向服务器公网 IP。
2. Nginx 将域名转发到前端容器。
3. 使用 Certbot 或云厂商证书配置 HTTPS。
4. 将 HTTP 重定向到 HTTPS。
5. 更新前端和后端的跨域、回调及安全配置。
