# 校园智能问答助手上线方案

> 本方案针对当前 Windows + Docker Compose 项目，先完成可回滚的本地生产验证，再部署到具备公网 IP 的 Linux 云服务器。

## 目标

完成一套可重复、可回滚、不会删除业务数据的上线流程：代码进入 Git，配置通过环境变量注入，前端、后端、MySQL、Redis 和 Dify 的职责分离，发布前通过登录、聊天、知识库和管理员功能验收。

## 当前结论

- 前端是 Vue 3 + Vite，适合构建静态资源后由 Nginx 提供服务。
- 后端是 Spring Boot 3 + Java 17，适合构建 Docker 镜像运行。
- MySQL 数据卷为 `mysql_data`，发布时不能使用 `docker compose down -v`。
- 当前 Dify 数据库和 API 已由现有 Dify Compose 管理，业务后端应通过共享 Docker 网络访问匹配版本的 Dify API，不能启动另一套不匹配版本。
- 当前没有 Git 仓库，也没有远程仓库地址；公网发布在获得服务器、域名和密钥前不能完成。

## 阶段一：代码与配置

1. 创建根目录 `.gitignore`，排除环境文件、Token、Cookie、Dify 备份、构建产物、日志和临时脚本。
2. 保留 `.env.example`，其中只放变量名和占位值，不放真实密码或 API Key。
3. 生产服务器单独创建 `.env`，不提交 Git。
4. 更换曾经出现在本地配置或聊天记录中的数据库密码、JWT 密钥、Dify Secret 和应用 API Key。
5. Git 初始化后先检查 `git diff --cached` 和敏感词扫描，再提交。

## 阶段二：本地生产验证

```powershell
cd D:\school-ai
docker compose config
docker compose up -d --build
docker compose ps
```

验收项目：

- `POST /api/auth/login` 返回 200 且中文姓名正常；
- 普通用户聊天返回 SSE；
- 知识库回答包含检索内容；
- 超级管理员文档列表、登记和删除正常；
- 前端窄屏布局正常；
- MySQL、Redis、Dify 数据卷没有被删除。

## 阶段三：云服务器部署

服务器要求：Ubuntu 22.04/24.04，至少 4 vCPU、8 GB RAM、80 GB 磁盘；开放 80/443/22，禁止公网开放 3306/6379。

1. 安装 Docker、Compose 插件和 Nginx。
2. 通过 Git 拉取代码到 `/opt/school-ai`。
3. 在服务器创建 `.env`。
4. 配置 Dify 使用已备份且版本匹配的 PostgreSQL、Redis、存储和模型供应商。
5. 使用域名指向服务器，Nginx 转发前端并配置 HTTPS。
6. 先备份 MySQL、Dify PostgreSQL 和 Dify 存储，再执行 `docker compose up -d --build`。
7. 用测试账号和真实测试问题完成验收后开放给用户。

## 后续发布与回滚

- 修复流程：本地修改 -> 前端构建/后端测试 -> Git 提交 -> 测试环境 -> 数据库备份 -> 正式更新。
- 仅前端变更：重建 frontend；仅后端变更：重建 backend；配置变更：重新创建相关容器。
- 回滚代码使用上一个 Git 提交，不删除数据卷。
- 数据库结构变更使用独立迁移 SQL，不依赖 `db/init.sql` 自动重复执行。
- 禁止在生产环境执行 `docker compose down -v`。
