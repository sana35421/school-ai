# 校园智能问答助手部署指南

本指南说明如何在 Windows Docker Desktop 或 Ubuntu 云服务器上部署当前版本。项目业务容器只包含 MySQL、Redis、Spring Boot 后端和 Nginx 前端；Dify 使用 Dify Cloud 或独立维护的 Dify 服务，不默认启动项目内的旧版 Dify 镜像。

## 一、部署架构

```text
用户浏览器
    |
    v
Nginx 前端 :80/:443
    |
    v
Spring Boot 后端 :8080 ---- MySQL :3306
          |
          +------------------ Redis :6379
          |
          +------------------ Dify API
```

公网环境只开放 22、80、443。MySQL 和 Redis 只能在 Docker 内网访问，不要映射到公网网卡。

## 二、准备 Dify

1. 在 Dify Cloud 或独立 Dify 服务中创建聊天应用。
2. 配置 DeepSeek 等模型供应商。
3. 创建知识库，上传经确认的校园政策、竞赛说明和常见问题资料。
4. 将知识库关联到聊天应用并发布。
5. 复制应用 API Key，并保存到本地或服务器 `.env`。

推荐系统提示词和知识库文件位于项目根目录：

- `computer_competition_system_prompt.md`
- `computer_competition_knowledge_base.md`
- `computer_competition_teammates_kb.md`
- `competitions_kb.txt`

其中队友联系方式属于演示数据，正式使用前必须取得本人同意并核对信息。

## 三、Windows 本地部署

### 3.1 启动 Docker Desktop

打开 Docker Desktop，等待 Docker Engine 显示运行正常：

```powershell
docker info
docker compose version
```

### 3.2 配置环境变量

```powershell
cd D:\school-ai
Copy-Item .env.example .env
notepad .env
```

填写真实值，不要把密钥直接写入代码：

```env
MYSQL_PASSWORD=强数据库密码
DIFY_API_BASE=https://api.dify.ai/v1
DIFY_API_KEY=app-有效的Dify应用Key
JWT_SECRET=至少32位随机字符串
```

### 3.3 启动和验收

```powershell
docker compose config
docker compose up -d --build
docker compose ps
```

访问 `http://localhost`，使用测试账号验证登录、中文姓名、历史对话和聊天流式输出。

查看日志：

```powershell
docker compose logs --tail=100 backend
docker compose logs --tail=100 frontend
```

## 四、Ubuntu 云服务器部署

### 4.1 服务器要求

- Ubuntu 22.04 或更高版本
- 至少 4 核 CPU、8 GB 内存、40 GB 可用磁盘
- 建议配置 2 GB Swap
- 安全组开放 22、80、443
- 安全组禁止 3306、6379
- 已安装 Docker Engine 和 Docker Compose 插件

### 4.2 获取代码

```bash
sudo mkdir -p /opt/school-ai
sudo chown -R "$USER":"$USER" /opt/school-ai
cd /opt/school-ai
git clone https://github.com/sana35421/school-ai.git .
```

如果服务器不能稳定访问 Docker Hub，可以在本地导出镜像后上传：

```powershell
docker save school-ai-backend:latest school-ai-frontend:latest mysql:8.0 redis:7-alpine nginx:latest -o school-ai-images.tar
scp .\school-ai-images.tar root@服务器公网IP:/opt/school-ai/
```

服务器导入：

```bash
cd /opt/school-ai
docker load -i school-ai-images.tar
```

### 4.3 创建服务器环境文件

```bash
cd /opt/school-ai
cp .env.example .env
nano .env
```

Dify Cloud 示例：

```env
MYSQL_PASSWORD=服务器专用强密码
DIFY_API_BASE=https://api.dify.ai/v1
DIFY_API_KEY=app-有效的Dify应用Key
JWT_SECRET=服务器专用随机密钥
```

保存后检查配置：

```bash
docker compose config --services
docker compose config --quiet
```

默认服务应为 `mysql`、`backend`、`frontend`、`redis`。不要启用 `local-dify` profile，除非已经准备好版本匹配的完整 Dify 依赖服务。

### 4.4 启动业务服务

使用已导入镜像时：

```bash
docker compose up -d
docker compose ps
```

如果服务器可以拉取基础镜像并且需要重新构建：

```bash
docker compose up -d --build
```

等待 MySQL 显示 `healthy`，再访问服务器公网 IP：

```text
http://服务器公网IP
```

### 4.5 发布新版本

本地完成修改和验证后：

```bash
git add .
git commit -m "描述本次修改"
git push origin main
```

服务器发布：

```bash
cd /opt/school-ai
git pull --ff-only origin main
docker compose up -d --build backend frontend
docker compose ps
```

如果只修改前端，重建 `frontend`；只修改后端，重建 `backend`。配置文件变更后重建或重新创建对应容器。

## 五、数据库备份与回滚

备份前确认容器名称：

```bash
docker compose ps
```

备份 MySQL：

```bash
mkdir -p /opt/school-ai/backups
docker exec school-ai-mysql mysqldump -uroot -p"$MYSQL_PASSWORD" school_ai > /opt/school-ai/backups/school_ai_$(date +%F_%H%M).sql
```

恢复前先停止后端写入，再导入备份：

```bash
docker exec -i school-ai-mysql mysql -uroot -p"$MYSQL_PASSWORD" school_ai < /opt/school-ai/backups/备份文件.sql
docker compose restart backend
```

代码回滚使用上一个 Git 提交：

```bash
git log --oneline -5
git checkout 上一个稳定提交
docker compose up -d --build
```

生产环境禁止执行：

```bash
docker compose down -v
```

该命令可能删除数据库和缓存数据卷。

## 六、常见故障

### 前端容器反复重启

查看 Nginx 日志：

```bash
docker compose logs --tail=100 frontend
```

如果出现 `host not found in upstream`，说明 `frontend/nginx.conf` 中的代理地址指向了不存在的 Docker 容器。当前前端只应代理后端 `/api/`；Dify Cloud 请求应由后端访问，不要把本地容器名写入生产镜像。

### 登录返回 401

检查：

1. 账号和密码是否正确。
2. MySQL 是否已健康启动。
3. 后端日志是否显示 JWT 或数据库错误。
4. 前端请求是否为 `/api/auth/login`。

### 中文乱码

确认 MySQL 使用 `utf8mb4`，后端使用 `server.servlet.encoding`，并检查数据库中保存的数据本身没有重复编码。

### 聊天返回 500

检查：

1. `DIFY_API_BASE` 是否包含 `/v1`。
2. `DIFY_API_KEY` 是否为当前已发布应用的 Key。
3. Dify 应用是否关联知识库和模型。
4. 后端容器是否能访问 Dify API。

### SSE 中途断开

Nginx `/api/` 配置必须保留：

```nginx
proxy_buffering off;
proxy_cache off;
proxy_read_timeout 300s;
```
